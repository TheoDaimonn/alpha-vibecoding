# Аудит runtime-кода — 2026-09-23

Проверены API, engine/batcher, memory/Redis, маскирование, model wrappers, student,
ONNX, правила, UI, конфигурация, Docker и скрипт SSH-туннеля.
Это самостоятельный аудит: подробности внешних 9 замечаний не предоставлены,
поэтому сопоставить исправления с CRITICAL/MAJOR внешней проверки нельзя.

## Контракт — без изменений

В runtime-ветке нет `rules/`. Прочитаны PDF критериев из `origin/main:rules/`
и приложение A/B из `origin/main:Hackathon task.md`.

`POST /process`: `{payload, payload_id}` → `{result}`; оба входных поля обязательны.
Никаких `operation`, дополнительных обязательных ключей, отдельного endpoint или
разделения хранилища по API-ключам не добавлено. Ранее предложенные изменения
этого поведения удалены по требованию пользователя.

Демаскирование возвращает всю исходную строку при совпадении payload с сохранённой
маской для того же ID. Другие запросы с этим ID возвращают сохранённую маску.
Контракт из двух входных полей сохранён.

## Подтверждённые проблемы и исправления

| Проблема | Исправление и проверка |
|---|---|
| `Future` изменялся из executor-потока | Завершение future только в event loop; asyncio debug-тесты |
| Stop не ожидал работников, повторный start не работал | Ожидание работников, завершение ожидающих запросов, тест рестарта/остановки во время инференса |
| Ожидание места в очереди не входило в таймаут | Немедленный 429 при заполнении; ограничения числа и суммарной длины текстов |
| `Retry-After` терялся при HTTPException | Заголовок передаётся в HTTPException |
| Memory TTL игнорировался | Monotonic deadlines, очистка истёкших записей при обращении, тест времени |
| Параллельные записи меняли оригинал по ID | Atomic first-writer-wins: lock в memory, Lua в Redis; тесты конкурентных запросов |
| Неизвестный backend молча выбирал memory | Ошибка конфигурации вместо незаметной потери общего хранилища |
| Независимые Redis-записи correlation/result расходились | Engine сохраняет одну целостную запись; отдельный result-cache больше не используется в API |
| Ошибки Redis не учитывались при обработке API | Чтение и обработка в общей границе ошибок; сокетные таймауты Redis |
| Невалидные спаны молча пропускались | Ошибка вместо потенциальной утечки; строгая проверка восстановления |
| Маскирование повторно обходило вложенные интервалы | Маскирование объединения интервалов; 250 детерминированных случайных round-trip примеров |
| Hybrid отбрасывал модельные сущности некоторых типов | Регулярные выражения дополняют, а не заменяют обнаруженное моделью |
| Слова «врач», «банк» снимали маскирование соседних ПД | Удалены эвристические исключения; только явные вспомогательные PUBLIC-метки |
| ONNX оставлял начало email открытым в длинном примере | Дополнение полным email-спаном; regression + настоящая модель |
| Student молча отбрасывал хвост после 512 символов | Перекрывающиеся окна и перенос оффсетов, ограниченные батчи окон; тест на 1500 символов с управляемой моделью |
| Wrapper-ы могли молча обрезать батч через zip | Проверки числа результатов и strict zip |
| LFS-указатель попадал в бинарный загрузчик | Явная проверка файла с инструкцией скачать LFS и пересобрать образ |
| Несколько API-процессов могли использовать разрозненный memory | Валидация конфигурации при запуске |
| `/health` всегда был OK | Проверка работников и доступности хранилища |
| Счётчик total не включал ошибки/перегрузку | Согласованные total/successful, явно указан scope latency |
| UI мог смешивать ID/ответы при повторных кликах | Блокировка параллельных действий, новый ID фиксируется после успешного маскирования |
| UI не передавал настроенный API-ключ | Поле ключа в памяти страницы, передача X-API-Key |
| Импорт rules/core тащил нейросетевые зависимости | Отложенный импорт нейросетевых backend-ов в factory |
| API-образ работал от root | USER 10001:10001; проверочный образ собран отдельно |

## Проверки и границы доказательств

- Unit/HTTP/конкурентные тесты выполняются на Python 3.10 в Docker; реальные Lua/TTL проверяются в отдельном Redis без рабочих данных.
- ONNX smoke: короткий, пустой и длинный текст; окно 256, stride 64, batch 1. Проверяются полное покрытие email и точное восстановление.
- Попытка ONNX с исходными большими окнами завершилась кодом 137. В момент проверки Docker имел 3,8 ГБ RAM, сторонний API занимал примерно 2,3 ГБ. Возможная причина — нехватка памяти; чужие контейнеры не останавливали.
- Ruff, compileall, проверка JavaScript через `node --check`; Docker-образ собирается отдельно от работающего сервиса.
- Тексты ошибок моделей/хранилища могут включать входные данные, поэтому обработчик логирует тип ошибки без её содержимого. Это уменьшает подробность диагностики.

## Оставшиеся ограничения

1. Recall ≥0.95, 1000/2000 RPS и latency ≤1 с **не доказаны**. Нужны размеченный корпус и нагрузочная проверка, включая большие тексты. Полное восстановление сохранённой строки не доказывает полноту обнаружения ПД.
2. Regex-backend маскирует любые отдельные 3/4-значные числа как CVV/PIN; у него есть неоднозначность дат и документов. Общая перестройка таксономии требует проверки на эталонах. В ONNX автоматически добавлены только email-спаны.
3. Реальный student-checkpoint в этой сессии не оценивался. Окна проверены на управляемом декодере; качество на границах окон и влияние padding у BiLSTM требуют оценки на корпусе.
4. После TTL восстановить оригинал невозможно. Контракт из двух полей не различает истёкшее демаскирование и новый запрос: неизвестный ID обрабатывается как новый.
5. API-ключи имеют общее пространство ID — это сохранённое поведение по требованию пользователя. Без API_KEYS доступ открыт. ID должен быть уникальным между потребителями; ключи и исходные строки в URL не передавать.
6. Redis хранит оригиналы открытым текстом, Compose включает AOF. TTL не является гарантией физического уничтожения данных на диске. Шифрование и политика хранения не добавлены в этот рефакторинг.
7. Memory очищает истёкшие записи при обращении, не по фоновому таймеру. Общий размер хранилища оригиналов не ограничен; ограничения очереди не являются лимитом памяти всего приложения.
8. Параллельные дубликаты могут повторно вычисляться моделью. Атомарная запись сохраняет согласованность результата, но не обеспечивает exactly-once инференс.
9. Диапазоны зависимостей и базовые образы не зафиксированы по digest/lock. Проверка согласованности пакетов не заменяет CVE-аудит; сканирование CVE не выполнялось.
10. Бесплатный SSH-туннель, его доступность и стабильность URL не проверялись нагрузкой. Метрики остаются локальными для процесса, а не агрегированными по всем worker-ам.
11. Отмена asyncio не прерывает выполняющийся нативный инференс. При остановке engine ожидает его завершения; зависший нативный вызов требует внешнего process timeout.

Исправления находятся в рабочей папке. Рабочий API и публичный туннель в рамках аудита не перезапускались.

## Оптимизация пула

Добавлен выделенный ThreadPoolExecutor на процесс, асинхронные чтения Redis,
сериализация только токенизации общего tokenizer и явные пределы native-потоков.
Compose: 2 процесса × 2 потока инференса, до 6 CPU и 4 ГБ, batch wait 5 мс.
Настройки проверяются функциональными тестами; сравнительный throughput-бенчмарк
не проводился из-за установленного пользователем трёхминутного лимита.
