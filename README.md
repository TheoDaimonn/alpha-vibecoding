# PII API — runtime

Ветка содержит student и RuBERT-tiny2 ONNX int8, инференс, FastAPI, Redis и SSH-туннель.
Обучения, корпусов, ноутбуков и GLiNER-весов здесь нет.

```bash
git clone --depth 1 --single-branch --branch runtime-only https://github.com/TheoDaimonn/alpha-vibecoding.git
cd alpha-vibecoding
git lfs install
git lfs pull --include="artifacts/**"
docker compose up --build
```

API: http://localhost:8000/docs. После подключения туннель печатает PUBLIC_URL.
Текущая ссылка: `docker compose exec -T tunnel cat /run/tunnel/public-url`.
Для локального запуска: `docker compose up --build redis api`.

`POST /process`: `{"payload":"текст", "payload_id":"уникальный-id"}` → `{"result":"маска"}`.
Повторите запрос с маской и тем же ID для демаскирования.
`/health`, `/metrics`, `/ui` — состояние, метрики и ручная проверка.

Переменные Compose: `API_PORT=8000`, `API_WORKERS=2`, `API_KEYS` (список через
запятую, клиент передаёт X-API-Key). По умолчанию API доступен без ключа.
Redis используется для общего хранения корреляций между процессами.

Student обрабатывает текст перекрывающимися окнами по 512 символов; хвост документа не отбрасывается. Recall 0.95 и 2000 RPS не подтверждены.
Бесплатный туннель localhost.run имеет ограничения, адрес может меняться.
RuBERT-base из Kaggle ещё не интегрирован; ONNX здесь — отдельный rubert-tiny2.

Для запуска без Docker: Python 3.10+, `pip install -r requirements.txt`,
затем `python -m src.run_api` из корня. Локально по умолчанию один процесс
и хранилище в памяти; для нескольких процессов необходим общий Redis.



`cp .env.example .env && docker compose up --build` запускает ONNX-детектор.
Без `.env` остаётся student. Переменные экспортированного окружения имеют
приоритет над `.env`. Для прямого запуска Python переменные надо экспортировать;
пути `/app/...` из примера предназначены для контейнера.

`RUBERT_MODEL_PATH` — каталог ONNX и tokenizer; `RUBERT_MAX_LEN` / `RUBERT_STRIDE`
задают окно и перекрытие (пустые значения берутся из checkpoint).
`MODEL_BATCH_SIZE` — число окон в ONNX-батче, `ONNX_INTRA_THREADS` /
`ONNX_INTER_THREADS` — потоки ONNX Runtime; провайдер CPU.
Невалидное окно, stride, batch или число потоков приводят к ошибке при загрузке.
`WORKER_*` управляют очередью API; `API_WORKERS` — число процессов с отдельной
копией модели. По умолчанию один процесс. `POSTPROCESS` — дополнительный
фильтр явных PUBLIC-меток, выключен; слова «врач» и «банк» больше не исключают персональные сущности. ONNX исключает PUBLIC-метки независимо от него.
`THRESHOLD` не применяется к ONNX BIO-декодеру.

`API_PORT` меняет порт хоста; внутри Compose API всегда слушает 8000.
Для Python напрямую доступны `HOST` и `PORT`. `API_KEYS` задаёт ключи через запятую.
Меняя путь модели в контейнере, обеспечьте наличие каталога внутри образа или
подключите volume. Изменения `.env` применяются пересозданием контейнера.


### Внутренняя логика и контракт

Контракт приложения A не менялся: `POST /process`, запрос строго из двух полей
`{"payload":"...","payload_id":"..."}`, ответ `{"result":"..."}`.
Новых полей или режимов нет. Новый ID запускает маскирование и сохраняет оригинал.
При совпадении payload с сохранённой маской для этого ID возвращается оригинал.
Другой payload с тем же ID получает сохранённую маску для идемпотентных ретраев.
Оригинал берётся из хранилища целиком, без восстановления по спанам.
API-ключ проверяет доступ, но не меняет ID и не создаёт отдельного пространства данных.

Запись по ID создаётся атомарно: конкурирующий запрос не перезаписывает первый оригинал.
TTL (`RESULT_TTL_S`) действует в Redis и memory. После истечения TTL ID снова считается новым;
оригинал уже недоступен. В memory истёкшие записи очищаются при следующем обращении.
Для нескольких процессов требуется Redis; сочетание нескольких процессов и memory отклоняется при запуске.

`WORKER_QUEUE_SIZE` (по умолчанию 256) ограничивает очередь, `WORKER_QUEUE_CHARS`
(4000000) — суммарный объём текстов в очереди и выполняющихся батчах. Перегрузка
возвращает предусмотренный контрактом 429 с `Retry-After: 1`.
`/health` проверяет работников и доступность хранилища.
`/metrics`: `total` включает успешные запросы, ошибки обработки и перегрузку;
`avg_latency_s` относится к успешным запросам, счётчики остаются на процесс.

ONNX-декодирование дополнено поиском полных email-адресов, чтобы частичный BIO-спан
не оставлял часть адреса открытой. Это не доказательство recall ≥0.95.
Пустой/неполученный Git LFS файл модели теперь даёт понятную ошибку при загрузке.

### Проверки

При установленных runtime-зависимостях: `python -m unittest discover -s tests -v`.
Интеграционный тест Redis включается через `REDIS_TEST_URL` (только тестовая база),
ONNX smoke — через `RUN_ONNX_SMOKE=1` при скачанной модели.
Статический анализ: `pip install -r requirements-dev.txt`, затем
`ruff check src ru_pii tests deploy`. Итоги и ограничения аудита — в `AUDIT.md`.


### Параллелизм

Compose по умолчанию запускает 2 API-процесса, каждый с отдельным пулом из 2 потоков
инференса. Redis общий; чтение при маскировании и демаскировании асинхронное.
Итого до 4 одновременно выполняемых батчей; ONNX intra/inter threads — по 1.
Tokenizers/OpenMP/MKL не создают дополнительные большие пулы. Сбор батча ждёт до 5 мс.
Лимиты контейнера: `API_CPUS=6`, `API_MEMORY_LIMIT=4g`; это верхние границы,
а не заранее зарезервированные ресурсы. На меньшей машине уменьшите API_WORKERS.
Число копий модели равно API_WORKERS. Масштабирование по контейнерам без балансировщика
не настроено. Ускорение на полном нагрузочном наборе ещё не измерено.
